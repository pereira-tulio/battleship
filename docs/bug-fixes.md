# Bug fixes and risk validation

Entries are labeled by provenance: the earlier rows came from code review or
focused regression testing, while the final two rows came from a manual browser
playtest and are covered by the named UI regressions.

| Bug/risk identified                                                   | How reproduced or detected                                                                                                                   | Root cause                                                                                                                                                                   | Fix implemented                                                                                                            | How validated                                                                                                                                                                      |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reducer could make divergent AI decisions in StrictMode               | Code review found `Date.now()` inside the `ai-fire` reducer branch                                                                           | Reducers must be pure, and StrictMode may invoke them more than once                                                                                                         | State now carries an incrementing seed; AI receives a deterministic RNG derived from that seed                             | `keeps the AI reducer branch deterministic for StrictMode` and UI flow                                                                                                             |
| Hunt parity used the largest remaining ship                           | Code review compared the implementation with the stated minimum-length strategy                                                              | Candidate mask used `Math.max` instead of the smallest live ship size                                                                                                        | Hunt mode now derives parity from the minimum remaining length                                                             | `uses the minimum remaining ship length for hunt parity`                                                                                                                           |
| Only the final sunk cell was marked sunk                              | Combat review and a renderer inspection showed previous cells remained `hit`                                                                 | `fireAt` only wrote the latest shot key                                                                                                                                      | A sunk result marks every cell in that ship as `sunk`                                                                      | `reports miss, hit, sunk and win` checks both ship cells                                                                                                                           |
| Keyboard navigation could dead-end on fired cells                     | Code review found fired cells were disabled before arrow navigation                                                                          | Disabled buttons cannot receive focus                                                                                                                                        | Cells remain focusable and use `aria-disabled`; activation is a no-op when locked                                          | UI flow covers the focusable semantic grid                                                                                                                                         |
| Grid ARIA structure was invalid                                       | Accessibility review found 100 direct gridcell children                                                                                      | ARIA grids require row grouping                                                                                                                                              | Boards now render ten `role="row"` wrappers                                                                                | UI test queries semantic grids and rendered rows                                                                                                                                   |
| Player fleet remained wired for interaction during play               | Code review found the player board always received placement callbacks                                                                       | Board interaction was not phase-gated                                                                                                                                        | `interactive` is true only during placement; firing is enabled only on player turn                                         | Full UI flow verifies phase-specific actions                                                                                                                                       |
| Stale AI timeout could land after New Game                            | Fake-timer scenario was identified during reducer/hook review                                                                                | A queued timeout could dispatch after a reset                                                                                                                                | Timer cleanup plus reducer phase guards prevent stale actions                                                              | UI flow advances timers after New Game and verifies zero hits taken                                                                                                                |
| Vertical and negative placement boundaries were easy off-by-one cases | Boundary-focused placement tests                                                                                                             | Validation must inspect every generated cell, not only its origin                                                                                                            | `canPlaceShip` validates all generated coordinates                                                                         | Placement orientation/boundary cases in `game.test.ts`                                                                                                                             |
| Placement-phase helper copy was mis-gated                             | Manual browser playtest on first load showed Your waters said “Select a coordinate to fire.”                                                 | Helper text was derived from phase only, not panel role                                                                                                                      | `BoardPanel` now derives copy from panel role plus phase                                                                   | `shows role-specific helper copy during placement`; `updates both helper messages during the player turn`                                                                          |
| Placement hover preview became stale or misleading                    | Manual browser playtest found previews persisted after leaving the grid, turned red after Random placement, and truncated out-of-bounds runs | Hover state was not cleared when leaving or changing placement state, and preview rendering only considered in-bounds cells without an explicit invalid-footprint regression | Clear hover on mouse leave, blur, and placement changes; mark every visible cell in an out-of-bounds attempted run invalid | `clears placement hover preview when leaving the board`; `clears placement hover preview after random placement`; `marks every in-bounds cell of an out-of-bounds preview invalid` |
